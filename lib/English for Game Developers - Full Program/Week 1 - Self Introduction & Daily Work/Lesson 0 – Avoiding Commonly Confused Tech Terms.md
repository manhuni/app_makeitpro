# 🎯 **Lesson – Avoiding Commonly Confused Tech Terms**

> 📘 **Mục tiêu bài học:**

* ✅ Nhận biết và phân biệt rõ ràng các cặp từ dễ gây nhầm lẫn.
* ✅ Dùng từ chính xác trong họp, báo cáo, và khi giao tiếp với team đa ngành.
* ✅ Tăng tính chuyên nghiệp và hiệu quả giao tiếp trong môi trường quốc tế.

## 📚 **Phân biệt các cặp từ dễ nhầm lẫn**

| ✅ Từ 1                            | ❌ Nhầm với                          | 📎 Phân biệt rõ                                                                 | 📌 Ví dụ sử dụng                                              |
| --------------------------------- | ----------------------------------- | ------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| **Wireframe** /ˈwaɪə.freɪm/       | **Mockup** /ˈmɒk.ʌp/                | Wireframe là khung đơn giản đen trắng; Mockup có hình ảnh, màu sắc.             | *We need a wireframe before moving to mockups.*               |
| **Mockup**                        | **Prototype** /ˈprəʊ.tə.taɪp/       | Mockup là hình ảnh tĩnh, prototype có thể tương tác.                            | *This mockup looks great, but it’s not clickable yet.*        |
| **Prototype**                     | **Product** /ˈprɒ.dʌkt/             | Prototype là bản mẫu, chưa hoàn chỉnh; Product là sản phẩm thật.                | *We built a prototype for internal testing.*                  |
| **Library** /ˈlaɪ.brər.i/         | **Framework** /ˈfreɪm.wɜːk/         | Library là tập hợp hàm dùng khi cần; Framework định hình toàn bộ kiến trúc app. | *React is a library. Angular is a framework.*                 |
| **Debug** /ˌdiːˈbʌɡ/              | **Test** /test/                     | Debug là xử lý lỗi đã phát hiện; Test là tìm lỗi.                               | *I’ve tested it, now I’ll debug the errors.*                  |
| **Client** /ˈklaɪ.ənt/            | **Customer** /ˈkʌs.tə.mər/          | Client là bên làm việc trực tiếp (B2B); Customer là người dùng cuối.            | *Our client requested a redesign.*                            |
| **Agile** /ˈæ.dʒaɪl/              | **Scrum** /skrʌm/                   | Agile là triết lý phát triển; Scrum là một framework thuộc Agile.               | *We follow Agile methodology using Scrum.*                    |
| **Commit** /kəˈmɪt/               | **Push** /pʊʃ/                      | Commit lưu cục bộ, push đẩy lên repository.                                     | *Don’t forget to push after committing.*                      |
| **Merge** /mɜːdʒ/                 | **Rebase** /ˈriː.beɪs/              | Merge giữ lịch sử; Rebase thay đổi dòng thời gian commit.                       | *Use rebase for clean history; merge for preserving context.* |
| **UI (User Interface)** /ˌjuː.aɪ/ | **UX (User Experience)** /ˌjuː.ɛks/ | UI là giao diện; UX là trải nghiệm tổng thể.                                    | *UX is about feeling; UI is about look.*                      |
| **Font** /fɒnt/                   | **Typeface** /ˈtaɪp.feɪs/           | Typeface là họ chữ (e.g. Roboto), Font là biến thể (e.g. Roboto Bold).          | *Choose a readable typeface and limit font weight.*           |
| **Latency** /ˈleɪ.tən.si/         | **Lag** /læɡ/                       | Latency là độ trễ kỹ thuật; Lag là cảm giác bị chậm.                            | *High latency often causes visible lag.*                      |
| **Version** /ˈvɜː.ʃən/            | **Release** /rɪˈliːs/               | Version là số hiệu; Release là hành động tung ra.                               | *The latest release is version 2.3.0.*                        |
| **Feature** /ˈfiː.tʃər/           | **Function** /ˈfʌŋk.ʃən/            | Feature là tính năng người dùng thấy; Function là đoạn mã thực thi.             | *We added a login feature using a new function.*              |

## ✍️ Bài luyện viết (Writing Practice)

> Viết 5 câu mô tả quá trình làm việc giữa dev và designer, sử dụng đúng các từ:

* wireframe
* mockup
* prototype
* feedback
* user flow

**Ví dụ:**

1. I created a wireframe to illustrate the basic layout of the app.
2. After the designer sent the mockup, I implemented the UI in React.
3. We built a clickable prototype for the client to review.
4. The user flow was confusing, so we updated the navigation.
5. We collected feedback from testers and adjusted the layout accordingly.

---

## 🗣️ Bài luyện nói (Speaking Practice)

**Chủ đề:**

> Giải thích với quản lý sự khác nhau giữa mockup và prototype bằng tiếng Anh.

**Mẫu câu gợi ý:**

* "A mockup is just a static image showing what the final design will look like."
* "A prototype, on the other hand, allows interaction like clicking buttons or navigating screens."

---

## 📒 Ghi chú mở rộng

* Luôn xác định rõ mục đích: bạn muốn chia sẻ cái nhìn (mockup), cấu trúc (wireframe), hay hành vi thực tế (prototype)?
* Khi trao đổi với khách hàng hoặc team, nên nói rõ: "This is not functional yet – just a mockup."
* Trong dev workflow, việc hiểu đúng **library vs framework**, hay **commit vs push** sẽ giúp tránh lỗi Git và hợp tác trơn tru hơn.
